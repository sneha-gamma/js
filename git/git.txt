
Version Control System
VCS is a tool used in software dev and collabrative project to track and manage the 
changes to source code.

version -> specific snapshot of our project files at a particular point in time 
recorded through a commit

Components in VCS
1) repository -> central location that stores all project files along with their 
complete change history
 and metadata.

2)Revision -> A specific saved version of a file or project

3)Branch -> A separate copy of codebase used to develop feature or fix bugs 
without affecting the main code

4) Merging -> Combining changes from one branch to another
5) Commit -> a snapshot of chnages made to codebase at specific time used to track and manage project history

Types of VCS

1) Local VCS
store all project version on single system ans is mainly used by one user without
remote collaboration(RCS-> revision, source-code cs)

2) Centraliazed VCS (subversion,bazar, concurrent vs)
all files and version history are stored in a single central server
developers connect to this server to access or modify files

3) Distributed version  cs (git, mercurial,bazar)
allow each developer to have local repo along with a working copy of project
dvcs uses two-step process(commit-push) to share changes with other dev

types of repositories

1) bare repository
a repository without a working directory, typically used for 
sharing projects remotely

2) non-bare repo
a repo that includes a working directory where developers can modify and track files

How to rename branch locally
git branch -m <new-name>
git branch -m <old-name> <new-name>
use -M if only changing capitalization

How to rename branch remotely
first chnage locally
push the new branch(git push origin -u <new-name>)
delete old branch(git push origin --delete <old-name>)
